# 1.0.1 Fixes (Collie VS Code Extension)

Complete: 0%

## Context & Problem

The extension currently has several DX-trust issues:

- Default template IDs are over-engineered and awkward (`AnimalList.AnimalList`). We want simple IDs: `FileBase_1`, `FileBase_2`, ...
- The extension’s understanding of `#classes` (directive, indentation, alias naming, `$alias` tokenization) is out of sync with the compiler, causing bogus diagnostics and confusion.
- Diagnostics are inconsistent depending on which side changes (Collie vs TSX). Unknown ids in TSX should be an error, and the cross-file index needs correct invalidation so both sides update reliably.
- We want a quick fix for inline text errors (“Inline text must start with `|`”).
- We want a low-noise hint teaching the “explicit input key” pattern (`inputs={{ animal: a }}`) without changing the converter default output or spamming warnings.
- We’re intentionally allowing id collisions across directories; therefore, duplicate-id diagnostics in the IDE must be excellent.

This doc defines staged fixes to restore trust and align behavior with the compiler.

## Principles / Decisions

- Default IDs: `FileBase_1`, `FileBase_2`, ... (no scope segments, no directory disambiguation).
- Collie `#classes` is the only accepted directive; we don’t support older spellings.
- `#classes` alias names allow kebab/snake: `card-container`, `card_container`.
- `$alias` usage allows kebab/snake: `.$card-container`, `.$card_container`.
- TSX unknown template id is an error (not a warning).
- Collie unused id is a warning (not an error).
- No legacy/back-compat support paths.

## Stage 1 — Converter: default template IDs -> `FileBase_1`, `FileBase_2`, ...

Complete: 0%

### Goal

When converting JSX/TSX to Collie, generate ids like:

- `AnimalList_1`
- `AnimalList_2`
- ...

### Files (expected)

- `src/features/conversion/templateId.ts`

### Work

1. Remove `File.Scope` ID generation.
2. Determine base name from the target file:
   - `AnimalList.tsx` -> `AnimalList`
   - `index.tsx` -> use parent folder name (keep current behavior if it exists and is good)
3. Generate `base_1` and increment until the id is not already present in the target `.collie`.
4. Sanitize id consistently:
   - Keep to `[A-Za-z0-9_]+` (or reuse existing sanitize logic).
   - Ensure it starts with a letter; if not, prefix with `Template`.

### Expected outcome

- First conversion within `AnimalList.tsx` yields `AnimalList_1` by default.

### Acceptance criteria

- No more `File.File` IDs.
- Repeated conversions in the same file increment predictably.

## Stage 2 — Collie parsing/indexing: understand `#classes` + kebab aliases + `$alias` tokens

Complete: 0%

### Goal

The extension should treat valid `#classes` files as valid and stop producing bogus indentation / “must start with tag” errors.

### Files (expected)

- `src/lang/parseDocument.ts` (or equivalent Collie parse module)
- `src/lang/templateIndex.ts` (id + alias discovery)
- Any Collie tokenizer/parser utilities used for diagnostics

### Work

1. Directive recognition and block semantics
   - Recognize `#classes` as a real top-level directive.
   - Track its indentation level similarly to `#inputs`.

2. Alias definition parsing
   - Parse alias lines as: `alias-name = class.tokens`
   - Alias name regex:
     - starts with `[A-Za-z_]`
     - continues with `[A-Za-z0-9_-]*`
   - Store alias definitions in the parsed template/index structure.

3. `$alias` usage parsing
   - Recognize `$card-container` as a single token.
   - Avoid splitting on `-`.
   - Ensure any “undefined alias” diagnostics show the full alias.

### Expected outcome

- The IDE matches compiler expectations for `#classes`.

### Acceptance criteria

- The example `#classes` snippet is clean in VS Code (no bogus errors).
- Undefined alias errors (if applicable) reference the full alias name.

## Stage 3 — Inline text quick fix (compiler-aligned): “Prefix with `|`”

Complete: 0%

### Goal

When a Collie file has the inline-text rule violation (compiler code e.g. `COLLIE004`), the editor offers a “Quick Fix” to prefix inline text with `| `.

### Files (expected)

- `src/features/diagnostics/codeActions.ts`
- Diagnostics emission path for Collie syntax errors (where `COLLIE004` is surfaced)

### Work

1. Ensure the extension emits (or forwards) a diagnostic with:
   - `code: "COLLIE004"` (match compiler)
   - a range that points at the invalid inline text segment

2. Add a CodeAction for `COLLIE004`:
   - Title: `Prefix inline text with "|"`
   - Edit: insert `| ` at the start of the inline text segment (after indentation).

3. Safety checks
   - Do nothing if the segment already starts with `|`.
   - Apply only to the diagnostic line/range to avoid accidental edits.

### Expected outcome

- One click fixes the inline-text error.

### Acceptance criteria

- Quick fix appears for `COLLIE004`.
- Applying it makes the compiler error disappear on next save.

## Stage 4 — Cross-file id reference diagnostics: severity + correctness + invalidation

Complete: 0%

### Goal

Make id-reference diagnostics consistent regardless of edit direction (TSX -> Collie or Collie -> TSX):

- TSX `<Collie id="missing">` => error
- Collie `#id` not referenced => warning
- Diagnostics update when either TSX or Collie changes (no stale one-way behavior)

### Files (expected)

- `src/features/diagnostics/tsInputsDiagnostics.ts` (TSX Collie mount diagnostics)
- `src/features/diagnostics/helpers/templateUsage.ts` (Collie unused id detection)
- `src/lang/templateIndex.ts`
- Any cache/invalidation mechanism (`src/lang/cache.ts`, watchers, etc.)

### Work

1. Severity changes
   - Upgrade TSX “Unknown Collie template id …” from warning -> error.

2. Invalidation / refresh
   - Ensure the “known template ids set” is rebuilt when:
     - `.collie` changes
     - `.tsx/.jsx` changes (mount changes)
     - file create/delete/rename occurs
   - Ensure both diagnostics pipelines are rerun after index updates.

3. Message quality
   - Keep messages concise but actionable:
     - include missing id
     - include at least one hint (“Did you mean …?”) if cheap to compute

### Expected outcome

- No more “works when Collie changes but not when TSX changes” behavior.

### Acceptance criteria

- Changing ids on either side updates both sets of diagnostics promptly.
- TSX missing id is an error.

## Stage 5 — Low-noise hint: teach “explicit inputs key mapping” for ambiguous shorthand

Complete: 0%

### Goal

We keep default converter output as:

```tsx
<Collie id="..." inputs={{ a }} />
````

…but we want to gently teach devs that they can do:

```tsx
<Collie id="..." inputs={{ animal: a }} />
```

so their Collie file can use `animal` in `#inputs`.

### Constraints

* We do not attempt to guess a singular name.
* We do not want noisy warnings.

### Files (expected)

* TSX inputs diagnostics module (same area that inspects `<Collie ... inputs={{ ... }} />`)

### Work

1. Add an info/hint diagnostic when:

   * `inputs` is an object literal
   * it contains shorthand properties (`{ a }`)
   * the shorthand key is low-signal:

     * length <= 2, OR another conservative heuristic

2. Diagnostic text

   * Make it informative and brief:

     * Explain the explicit mapping pattern `inputs={{ animal: a }}` and why it helps.

3. Avoid spam

   * Do not show if the key is already descriptive (length > 2).
   * Optionally add a setting flag to disable later if needed.

### Expected outcome

* Devs discover the nicer pattern naturally without changing converter defaults.

### Acceptance criteria

* Hint appears only in obviously “ambiguous” shorthand cases.
* No hint for descriptive shorthand keys.

## Stage 6 — IDE duplicate template id diagnostics (workspace-wide)

Complete: 0%

### Goal

Since duplicate ids across directories are allowed to occur, the extension must surface clear duplicate-id errors directly in the editor.

### Files (expected)

* `src/lang/templateIndex.ts`
* Diagnostics emitter that targets Collie files / template id declarations

### Work

1. Index all template ids across the workspace:

   * `Map<id, { uri, range }[]>`

2. For ids with multiple definitions:

   * Emit an error diagnostic at each definition range:

     * “Duplicate template id "X" also defined in <other-file>”

3. Keep it stable

   * Use deterministic ordering (sort URIs/paths before constructing messages so diagnostics don’t flicker).

### Expected outcome

* Duplicate ids are immediately visible and actionable during editing.

### Acceptance criteria

* Two collie files defining the same id show errors in both files.
* Diagnostics include at least one other conflicting path.

## Notes / Non-goals (1.0.1)

* No legacy support or migration logic.
* No attempt to infer singular variable names from iterator variables.
* No behavioral changes to runtime compilation here (collie repo handles compiler/runtime).
